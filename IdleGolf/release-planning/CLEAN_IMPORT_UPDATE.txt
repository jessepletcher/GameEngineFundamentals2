Fixed behavior

- The payout text queue used suspended awaits on scene-owned timers. Destroying
  the scene during payouts left an orphaned timeout StringName. The queue now
  advances through scene-owned callbacks, preserving four individual payouts
  followed by a summary for a burst. Scene destruction cancels pending callbacks.
  Removed a fallback that could start a second queue worker while one was pending.
- The old save runner copied Godot into self-contained mode and allowed an editor
  profiler user:// directory error. It now uses isolated APPDATA/LOCALAPPDATA/temp
  directories and precreates its user-data directory. That error is no longer
  allowed. Self-contained editors are rejected to protect profile isolation.
- Editor debug/LSP/DAP ports no longer collide with an already-open editor.
  The debugger gets an available local port; LSP/DAP request OS-assigned ports.
  Any remaining socket failure fails validation.
- Fresh production-only demo/full copies import on their first attempt without
  the original UID/type-inference failures. No warm .godot cache is copied.

Enforcement

tools/godot_checks.py is shared by the source suites, clean-import runner, Windows
exporter and packaged-runtime tests. Every automated Godot run uses --verbose and
checks both stdout/stderr and the engine log. Nonzero exit codes, missing logs,
timeouts, script errors, warnings, UID fallbacks, failed assertions, ObjectDB/RID
leaks and orphan/unclaimed StringNames fail the run. Timeout output is retained.
Forced-stop workers have their pre-termination diagnostics checked separately;
their intentional killed exit status is not mistaken for a normal exit.

Python -O/PYTHONOPTIMIZE is rejected so fixture/content assertions cannot vanish.
Deliberate malformed-save tests allow only the exact ConfigFile EOF diagnostic
at disposable case paths, at most ten times in that stage. Save failure,
recovery and demo-import notices have exact per-stage occurrence budgets.
The import notice occurs twice because the migration save clears the notice and
then restores it for the player. No broad ERROR/WARNING suppression remains.

tools/check_release.py runs the diagnostic-gate tests, an empty-editor baseline,
production-only clean imports and runtime smoke tests, then all save, gameplay,
shutdown and audio suites. tools/export_windows.py requires these checks before
exporting and runs the packaged tests afterwards. There is no skip-checks option.
Source hashes must remain unchanged throughout. A successful manifest is written
only after everything passes, and records source/artifact/engine/template hashes,
log locations and validation results. Failed attempts can leave executables but
do not get a success manifest. This is a local command gate; it does not configure
GitHub branch protection or restrict manual Steam uploads.

The exported test setup now establishes the prior Market checkpoint before its
early Exit probe. Recovery tests verify the backup, explicitly commit recovered
progress, then require a clean normal launch. Test drivers remain outside the
shipping project and execute beside byte-identical disposable executable copies.
