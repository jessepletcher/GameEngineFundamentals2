Implemented policy

- Export presets are Windows Demo (demo feature), Windows Full (full feature),
  and Linux Demo (demo feature; Linux was not exported/tested in this batch).
- BuildProfile reads game/edition with feature overrides. The editor defaults to
  demo; changing game/edition to full allows full-content editor testing.
- Debug tools require both a debug runtime AND game/debug_tools=true. Release
  builds cannot enable F1 even if that setting is accidentally enabled.
- Keep application/config/name="IdleGolf" permanently. It determines user://.
  Windows saves stay under %APPDATA%/Godot/app_userdata/IdleGolf/.
- Demo keeps idle_golf_demo_v0_1.cfg for compatibility. Full uses idle_golf_full.cfg.
  These filenames are stable identities, not version numbers to change each release.
- Full imports demo progress only when its primary, pending and backup paths are
  all absent. The validated import is committed before gameplay. Demo files are
  read only: no writing, rotating or recovery archiving in the demo's slot.
- Primary demo progress is preferred; validated pending/backup progress can be
  imported if necessary. A newer-version source prevents downgrading to an old backup.
- Existing full saves/recovery files always take precedence, including damaged
  files. Import must never silently replace paid-game progress with demo progress.
- Unrecoverable/newer demo data blocks automatic import/saving and explains how
  to restore/update or explicitly Reset Game to start the full game fresh.
- Reset affects only the running edition, preserves recovery copies, and commits
  a reset save so restarting does not reimport the demo. Import write failures
  retain the imported session for retry and never alter the source demo.
- Full content availability uses the existing catalog. This does not complete
  unfinished courses, balance, descriptions or gameplay mechanics.

Additional shutdown fixes found during graphical testing

- Clear the custom mouse cursor while the rendering server is alive to release
  its retained texture reference. This removed graphical shutdown texture/RID errors.
- Replace main-scene SceneTreeTimers with owned one-shot Timer children. Pending
  delays now end with their scene on quit/reload; the observed timer-instance leak
  warning no longer appears. Delay durations and pause behavior are retained.
- Verbose logging in one final full run still reports two unclaimed StringNames
  (Node and timeout), without ERROR, RID or ObjectDB-instance leak warnings. This
  remaining diagnostic is recorded under B12, not presented as fully resolved.
